# API форума

Спецификация текущей реализации в `packages/server`. Все маршруты форума
защищены серверной проверкой сессии. Авторизация, профиль и лидерборд
предоставляются API курса и не реализуются собственными таблицами пользователей.

## Общие правила

- Базовый путь собственного API: `/forum`.
- При прямом локальном обращении: `http://localhost:3001/forum`.
- JSON-запросы отправляются с `Content-Type: application/json`.
- Ответы содержат JSON, кроме успешного удаления: `204` без тела.
- ID записей — положительные целые числа PostgreSQL `INTEGER`.
- В JSON-теле ID передаются числами, а не строками.
- В query и path ID передаются строками, затем проверяются сервером.
- Даты в ответах — строки ISO 8601, например `2026-10-08T10:00:00.000Z`.
- Сервер генерирует `id`, `createdAt`, `updatedAt`.
- `authorId` назначается из проверенной сессии. Поле автора из тела запроса
  не используется. Изменить автора через API нельзя.
- Заголовок и текст сохраняются после `trim()`. Длина проверяется через
  JavaScript `string.length`, то есть в кодовых единицах UTF-16.
- Текст является обычным текстом, а не HTML. При отображении клиент должен
  использовать экранирование React, без `innerHTML` и `dangerouslySetInnerHTML`.
- Списки возвращаются массивами. Пагинация и гарантированный порядок пока
  не реализованы; пустой список — `200` с `[]`.

## Аутентификация и права

Вход выполняется через прокси API курса: `POST /api/v2/auth/signin`.
Он передаёт данные в API курса и возвращает сессионные cookie для приложения.
OAuth также завершается через прокси API курса.

Каждый запрос форума проходит middleware `authenticate`:

1. Сервер получает заголовок `Cookie`.
2. Передаёт cookie в `GET https://ya-praktikum.tech/api/v2/auth/user`.
3. Проверяет ответ и сохраняет подтверждённые `id` и `login` в `res.locals.user`.
4. Только после этого выполняется контроллер форума.

Отсутствующая или недействительная сессия возвращает:

```http
HTTP/1.1 403 Forbidden
Content-Type: application/json
```

```json
{"reason":"Authentication required"}
```

Если сервис авторизации недоступен, возвращает неожиданный ответ или не отвечает
за 5 секунд, запрос форума отклоняется с `503`:

```json
{"reason":"Authentication service unavailable"}
```

Чтение и создание доступны всем авторизованным пользователям. Удаление записи
доступно только её автору. Автор топика не получает отдельного права удалять
чужие комментарии; однако удаление собственного топика удаляет его содержимое
каскадно. Ролей администратора и модератора пока нет.

Браузерные запросы используют `credentials: 'include'`. Cookie с `HttpOnly`
не читаются JavaScript. При SSR cookie передаются серверным запросом явно.
Секретные значения cookie не должны попадать в документацию или логи.

## Сущности

### Topic

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | ID топика |
| `title` | string | Название, 1–200 кодовых единиц после `trim()` |
| `authorId` | integer | ID автора из API курса |
| `createdAt` | string | Дата создания |
| `updatedAt` | string | Дата изменения |

Топик не содержит отдельного поля текста. Сообщения обсуждения хранятся
в комментариях. В ответе топика комментарии не подгружаются.

### Comment: комментарий и ответ

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | ID сообщения |
| `text` | string | Текст, 1–5000 кодовых единиц после `trim()` |
| `authorId` | integer | ID автора из API курса |
| `topicId` | integer | ID топика |
| `parentCommentId` | integer или null | ID родительского сообщения |
| `createdAt` | string | Дата создания |
| `updatedAt` | string | Дата изменения |
| `reactions` | Reaction[] | Подгружается при GET списка комментариев |

Ответы хранятся в той же таблице `comment`:

- `parentCommentId: null` — обычный комментарий к топику;
- `parentCommentId: 10` — ответ на сообщение с ID `10`;
- родитель должен существовать и принадлежать тому же топику;
- отвечать на ответы разрешено; явного ограничения глубины пока нет.

Отдельных модели `Reply` и маршрутов `/replies` нет. Список комментариев
возвращается плоским: клиент строит дерево по `parentCommentId`.
Изменение родителя существующего сообщения через API не предусмотрено.

### Reaction

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | ID реакции |
| `type` | string | `like`, `heart` или `laugh` |
| `authorId` | integer | ID пользователя, поставившего реакцию |
| `commentId` | integer | ID комментария или ответа |
| `createdAt` | string | Дата создания |
| `updatedAt` | string | Дата изменения |

Один пользователь может поставить разные эмоции одному сообщению, но каждую
эмоцию только один раз. Это обеспечивается уникальным индексом
`(commentId, authorId, type)` в БД.

## Маршруты

| Метод | Путь | Назначение | Успех |
|---|---|---|---|
| GET | `/forum/topics` | Список топиков | 200 |
| GET | `/forum/topics/:topicId` | Один топик | 200 |
| POST | `/forum/topics` | Создать топик | 201 |
| DELETE | `/forum/topics/:topicId` | Удалить свой топик | 204 |
| GET | `/forum/comments?topicId=1` | Все сообщения топика с реакциями | 200 |
| POST | `/forum/comments` | Создать комментарий или ответ | 201 |
| DELETE | `/forum/comments/:commentId` | Удалить своё сообщение | 204 |
| POST | `/forum/reactions` | Добавить реакцию | 201 |
| DELETE | `/forum/reactions/:reactionId` | Удалить свою реакцию | 204 |

Общие ошибки авторизации `403` и `503` возможны на каждом маршруте и имеют
приоритет перед валидацией контроллера.

### GET /forum/topics

Тело и параметры не требуются. Возвращает массив `Topic`:

```json
[
  {
    "id": 1,
    "title": "Как пережить пожар?",
    "authorId": 42,
    "createdAt": "2026-10-08T10:00:00.000Z",
    "updatedAt": "2026-10-08T10:00:00.000Z"
  }
]
```

Ошибка БД: `500`, `reason: "Не удалось получить топики"`.

### GET /forum/topics/:topicId

Возвращает один объект `Topic` в том же формате, без комментариев.

| Код | reason |
|---|---|
| 400 | Некорректный ID топика |
| 404 | Топик не найден |
| 500 | Не удалось получить топик |

### POST /forum/topics

```json
{"title":"Как пережить пожар?"}
```

Возвращает созданный `Topic` со статусом `201`.

| Код | reason |
|---|---|
| 400 | Ожидается JSON-объект |
| 400 | Название должно быть строкой |
| 400 | Название должно содержать от 1 до 200 символов |
| 500 | Не удалось создать топик |

### DELETE /forum/topics/:topicId

Удаляет свой топик. Вместе с ним БД удаляет все комментарии, вложенные ответы
и их реакции. Успех: `204` без тела.

| Код | reason |
|---|---|
| 400 | Некорректный ID топика |
| 404 | Топик не найден |
| 403 | Нельзя удалить чужой топик |
| 500 | Не удалось удалить топик |

### GET /forum/comments?topicId=1

`topicId` — обязательный одиночный query-параметр. Возвращает обычные комментарии
и ответы всех уровней одним массивом. У каждого сообщения есть `reactions`.

```json
[
  {
    "id": 10,
    "text": "Сначала почини стол.",
    "authorId": 42,
    "topicId": 1,
    "parentCommentId": null,
    "createdAt": "2026-10-08T10:01:00.000Z",
    "updatedAt": "2026-10-08T10:01:00.000Z",
    "reactions": []
  },
  {
    "id": 11,
    "text": "Спасибо!",
    "authorId": 43,
    "topicId": 1,
    "parentCommentId": 10,
    "createdAt": "2026-10-08T10:02:00.000Z",
    "updatedAt": "2026-10-08T10:02:00.000Z",
    "reactions": [
      {
        "id": 5,
        "type": "like",
        "authorId": 42,
        "commentId": 11,
        "createdAt": "2026-10-08T10:03:00.000Z",
        "updatedAt": "2026-10-08T10:03:00.000Z"
      }
    ]
  }
]
```

Несуществующий топик возвращает `404`, существующий без сообщений — `200` и `[]`.

| Код | reason |
|---|---|
| 400 | Параметр topicId должен быть строкой |
| 400 | Некорректный ID топика |
| 404 | Топик не найден |
| 500 | Не удалось получить комментарии |

### POST /forum/comments

Обычный комментарий:

```json
{"topicId":1,"text":"Сначала почини стол."}
```

Ответ на комментарий или ответ:

```json
{"topicId":1,"text":"Спасибо!","parentCommentId":10}
```

Если `parentCommentId` отсутствует или равен `null`, создаётся обычный комментарий.
Возвращает `201` и объект `Comment` без подгрузки `reactions`.

| Код | reason |
|---|---|
| 400 | Ожидается JSON-объект |
| 400 | Комментарий должен быть строкой |
| 400 | Комментарий должен содержать от 1 до 5000 символов |
| 400 | ID топика должен быть числом |
| 400 | Некорректный ID топика |
| 400 | Некорректный ID родительского комментария |
| 400 | Родительский комментарий относится к другому топику |
| 404 | Топик не найден |
| 404 | Родительский комментарий не найден |
| 500 | Не удалось создать комментарий |

### DELETE /forum/comments/:commentId

Удаляет собственный комментарий или ответ. БД каскадно удаляет все его вложенные
ответы, включая сообщения других авторов, и реакции удаляемых сообщений.
Успех: `204` без тела.

| Код | reason |
|---|---|
| 400 | Некорректный ID комментария |
| 404 | Комментарий не найден |
| 403 | Нельзя удалить чужой комментарий |
| 500 | Не удалось удалить комментарий |

### POST /forum/reactions

```json
{"commentId":11,"type":"like"}
```

`commentId` — положительное целое число не больше `2147483647`.
Тип эмоции должен в точности совпадать с `like`, `heart` или `laugh`.
Одинаково работает для обычных комментариев и ответов.
Возвращает `201` и созданный объект `Reaction`.

| Код | reason |
|---|---|
| 400 | Ожидается JSON-объект |
| 400 | Некорректный ID комментария |
| 400 | Допустимые реакции: like, heart, laugh |
| 404 | Комментарий не найден |
| 409 | Реакция уже добавлена |
| 500 | Не удалось добавить реакцию |

Дубликат не перезаписывает существующую реакцию. Можно удалить её и добавить снова.

### DELETE /forum/reactions/:reactionId

Удаляет только собственную реакцию. Успех: `204` без тела.

| Код | reason |
|---|---|
| 400 | Некорректный ID реакции |
| 404 | Реакция не найдена |
| 403 | Нельзя удалить чужую реакцию |
| 500 | Не удалось удалить реакцию |

## Формат ошибок и ограничения

Контроллеры и middleware возвращают ошибки в формате:

```json
{"reason":"Топик не найден"}
```

Клиент должен ориентироваться на HTTP-статус; `reason` предназначен для сообщения
пользователю. Внутренние ошибки БД не возвращаются клиенту.

Обработка синтаксически повреждённого JSON и превышения лимита тела выполняется
`express.json()`. Единый JSON-обработчик этих ошибок пока не добавлен: такие ответы
могут отличаться от описанного формата. Неподдерживаемый маршрут также не имеет
собственного JSON-ответа `404`.

В текущей реализации нет редактирования записей, пагинации, поиска, модерации
и загрузки профилей авторов. Ответы содержат `authorId`, но не `authorLogin`.
Обычный `sequelize.sync()` создаёт отсутствующие таблицы, но не изменяет
существующую схему при изменении моделей.
