## 2026-08-14 — Спринт 7 разгружен, проверочные задачи сдвинуты вперёд

**Решение.** Тесты базовых компонентов (12.3) — в спринт 4. Первый замер Lighthouse —
отдельная задача 11.14 в спринте 4, сразу после поднятия прод-стенда; 11.8 остаётся
оптимизацией и контрольным замером. Спайк совместимости Service Worker и SSR — задача
11.15 в спринте 5. Задача 7.3 (рассадка гостей) перенесена в спринт 4 к очереди 4.3,
от которой она зависит. Проверка закрытости приватных эндпоинтов (2.9) — в спринт 6,
после появления всех ручек форума.

**Причина.** В последнем спринте были сосредоточены все «проверочные» задачи (офлайн,
Lighthouse, тесты, финальный прогон) — каждая из них способна вскрыть недельную проблему
за неделю до сдачи, а буфера не было. Плюс 7.3 стояла на спринт раньше очереди,
которую использует.

**Последствия.** Спринт 7 загружен на 18.5 из 20 — появился резерв ~1.5 дня на находки
финального прогона. Спринты 3–6 загружены на 23–23.5 в пределах допустимых ~10% перегруза.

## 2026-08-14 — Удаление аватара не реализуем

**Решение.** В swagger API курса нет эндпоинта удаления аватара — есть только загрузка
(`PUT`). Принцип: если в API функциональности нет — не реализуем и обходных путей
не строим. Задача 5.8 сокращена (2 → 1.5 дня).

**Причина.** Требование чек-листа («удаление текущего аватара») неисполнимо силами
фронтенда, бэкенд авторизации — чужой сервис.

**Последствия.** Пункт чек-листа остаётся незакрытым — зафиксирован в `requirements.md`,
вопрос озвучить наставнику до защиты. Если у API появится delete — вернуть в 5.8.

## 2026-08-14 — SSR-сервер шаблона правим сами

**Решение.** `packages/client/server/index.ts` можно менять — отдельным PR и с описанием
зачем. Нужные правки собраны в задачу 1.15: серверный 5xx, статус 404 для несуществующих
роутов, `nonce` для styled-components под CSP.

**Причина.** В проде файл падает в собственном `catch`: там вызывается
`vite.ssrFixStacktrace`, а `vite` вне dev — `undefined`. Любая ошибка рендера даёт пустой
ответ — тот самый белый экран, которого по требованиям быть не должно. React ErrorBoundary
здесь не помогает: `renderToString` границами ошибок не ловится.

**Последствия.** Задачи 1.15 и 3.21 (проброс cookie в серверный `initPage`).

## 2026-08-13 — Планируем от 140 дней, разрыв закрываем резом объёма

**Решение.** Ёмкость — 4 человека × 20 часов × 14 недель = 140 дней, по 20 на спринт.
Часы не поднимаем, объём режем.

**Причина.** Понижающий коэффициент к этим 140 дням не применяем: 20 часов в неделю уже
учитывают учёбу, ревью и накладные, второй коэффициент оставил бы 98 дней против 156.5
работы. Поднимать часы до 25 — решение про личное время четверых человек, его не принимают
в документе.

**Последствия.** Разрыв 16.5 дня закрывается пересмотром оценок после спринта 1 и второй
волной резов по «красной линии», контрольная точка — конец спринта 3. P1 и P2 не берутся.
Отдельного спринта стабилизации нет: заморозка фич — середина седьмого спринта.

## 2026-08-13 — Стили только на styled-components, без препроцессоров

**Решение.** Стили пишем на styled-components, как в шаблоне. Отдельный препроцессор
(Sass, Less) не подключаем. Если понадобится формальная галочка PostCSS — добавляем
`postcss.config.js` с autoprefixer, это полчаса.

**Причина.** Курс называет «препроцессоры или PostCSS» в списке технологий, но в приёмочном
чек-листе такого пункта нет. styled-components внутри работает на stylis, PostCSS встроен
в Vite. Две системы стилей в одном проекте — это разъехавшаяся палитра и лишние правила
на ревью.

**Последствия.** Цвета берутся только из объекта темы. Stylelint, если берём, нужен
с синтаксисом `postcss-styled-syntax` — обычный конфиг не увидит стили внутри шаблонных
строк.

## 2026-08-13 — Прод в Yandex Cloud, Vercel для превью

**Решение.** Продакшен — один стенд в Yandex Cloud: `docker compose` с nginx (SSL и единый
origin), клиентским контейнером с SSR на Node, своим сервером и PostgreSQL. Vercel —
только превью-деплой пул-реквестов.

**Причина.** Статическая сборка на Vercel не запускает `packages/client/server/index.ts`,
то есть SSR в проде не работает, хотя на нём построен весь клиентский код. Второе: при
разных доменах cookie сессии API курса становится third-party для фронта, и проброс сессии
(2.5) не заработает ни в браузере, ни при серверном рендере. Единый origin через nginx
снимает обе проблемы сразу.

**Последствия.** Нужен свой домен и сертификат — задача 1.14. Домен фиксируем рано:
от него зависит `redirect_uri`, если возьмём OAuth. Превью на Vercel идёт без SSR — это
витрина для ревью, а не стенд, на котором меряют Lighthouse.

## 2026-08-13 — Своя сессия проверяется через API курса

**Решение.** Свой бэкенд не хранит пользователей. На каждый приватный запрос он
пробрасывает cookie в эндпоинт «текущий пользователь» API курса и по ответу решает,
пускать ли.

**Причина.** Авторизация целиком в чужом сервисе, дублировать её у себя — около десяти
лишних дней работы и рассинхрон данных.

**Последствия.** Нужен единый origin: dev-прокси локально, nginx в проде. Нужна
аккуратность с CORS, `credentials: 'include'` и `SameSite` у cookie.

## 2026-08-13 — Тема хранится в cookie

**Решение.** Тема — JS-объект с цветами, раздаётся через `ThemeProvider` styled-components
(так устроен шаблон). Выбор пользователя лежит в cookie, а не в LocalStorage,
и дублируется в БД. Canvas берёт цвета из того же объекта темы.

**Причина.** При SSR чтение темы из LocalStorage даёт мигание: сервер рендерит
светлую, клиент переключает на тёмную.

**Последствия.** Тема доступна на сервере. Палитра не дублируется между CSS и canvas.
LocalStorage остаётся для черновиков форм и последней партии.

## 2026-08-13 — Чистый Canvas API без библиотек

**Решение.** Зал рисуется примитивами через Canvas 2D. Ни Pixi, ни Phaser.

**Причина.** Требование курса сформулировано как «Canvas API». Объектов на экране
мало (около 20), сложных эффектов нет — библиотека не нужна.

**Последствия.** Спрайтов нет, всё рисуется прямоугольниками и кругами. Хит-тестинг
писать руками, поэтому клик по залу — P2, а ремонт стола делается кнопкой в панели
действий.

## 2026-08-13 — Стартуем с шаблона курса

**Решение.** Проект форкнут с `Yandex-Practicum/client-server-template-with-vite`.

**Причина.** Готовая монорепа, Vite, SSR, docker-compose с PostgreSQL,
линтеры и хуки. Собирать то же самое с нуля — потерянная неделя.

**Последствия.** Монорепа на Lerna, зависимости добавляются через
`yarn lerna add --scope`. SSR уже есть и накладывает ограничения на весь клиентский код.
