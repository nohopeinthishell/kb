# Требования курса

Источник — задание на разработку веб-приложения «Игра», курс «Мидл фронтенд-разработчик».

Приложение состоит из двух частей: **сама игра** и **«коммерческая» обвязка**
(авторизация, профиль, форум, лидерборд).

## Как читать этот файл

Файл собран из двух разных частей задания, и путать их нельзя:

- **Раздел 1 — приёмочный чек-лист.** По нему принимают проект. Сверяемся в начале
  каждого спринта: что закрыто, что в риске. Чекбоксы есть **только здесь**.
- **Раздел 2 — технологии курса.** Это описание стека («технологии, которые будут
  использованы»), а не список обязательств. Явное обязательство там ровно одно —
  указать версию Node. Колонка «статус» — наше решение по каждой строке.
- **Раздел 3 — необязательное.** Берём только после закрытия всего из раздела 1.

Если пункт не в разделе 1 — он не может быть причиной завести P0-задачу.

# 1. Приёмочный чек-лист

## 1.1 Экраны

Дизайн придумываем сами. Креативность приветствуется.

### Авторизация
- [ ] Поля: логин, пароль
- [ ] Ссылка на страницу регистрации
- [ ] При успешном входе — редирект на страницу игры
- [ ] Уже авторизованный пользователь, зайдя сюда, попадает на страницу игры
- [ ] При неудаче — одно или несколько сообщений об ошибках

### Регистрация
- [ ] Поля: имя, фамилия, почта, телефон, логин, пароль
- [ ] При успехе — редирект на страницу игры
- [ ] При неудаче — сообщения о том, какие поля не прошли валидацию

### Профиль
- [ ] Поля: имя, фамилия, никнейм, почта, телефон, пароль
- [ ] Аватар: загрузка нового и **удаление текущего**
      *(удаления аватара в API курса нет — по swagger есть только `PUT`. Не реализуем,
      решение от 2026-08-14 в `decisions.md`; озвучить наставнику)*
- [ ] Изменение данных происходит на этой же странице

### Игра
- [ ] Предзапуск (превью): выбор персонажа, рубашки карт или хотя бы прелоадер
- [ ] Сама игра
- [ ] Завершение: кто победил, с каким счётом, кнопки «играть заново» и «в главное меню»

### Лидерборд
- [ ] Таблица всех пользователей сервиса
- [ ] Сортировка по **любому** полю таблицы
- [ ] Колонки придумываем сами
- [ ] Данные в БД, взаимодействие через API

### Форум
- [ ] Список тем, создание новых тем
- [ ] Комментарии и **ответы на них**
- [ ] Поддержка Emoji
- [ ] Бэкенд («ручки») пишем сами

### Страница 404
- [ ] Сообщение о том, что пользователь заблудился
- [ ] Кнопка возврата в сервис

### Страница 5xx
- [ ] Вежливое сообщение, что сервис сломался и проблему уже устраняют

## 1.2 Игра

- [ ] 2D
- [ ] От 1 до 16 человек на одном устройстве (больше одного — необязательно)
- [ ] Реализована на TypeScript и Canvas API
- [ ] Интерфейс управления процессом: жизни, время, очки, имена персонажей,
      количество карт в руке — что подходит по механике
- [ ] Обработка начала и конца игры
- [ ] Превью или прелоадер

**Ограничение по библиотекам** (это требование, а не рекомендация):

- **Игра пишется самостоятельно**: только TypeScript, Canvas API и статика
  (спрайты, шрифты). Игровых движков и библиотек рендеринга быть не должно
- На клиенте **вне игры** — любые библиотеки
- На сервере — любые

## 1.3 Пользователь и формы

- [ ] Регистрация
- [ ] Авторизация
- [ ] Изменение данных
- [ ] Добавление аватара
- [ ] Выход из аккаунта
- [ ] Все поля форм содержат валидацию
- [ ] Отображаются ошибки ввода **и** ошибки результата отправки формы

## 1.4 Темы оформления

- [ ] Минимум две темы с переключением между ними
- [ ] Настройки темизации хранятся в PostgreSQL через Sequelize

## 1.5 Общие

- [ ] Все экраны свёрстаны, запрограммированы и корректно работают
- [ ] Проект на React, используются Redux и React Router
- [ ] Следуем SOLID, DRY, KISS
- [ ] Каждая страница — отдельный роут; при обновлении пользователь остаётся на нём же
- [ ] Подключена HTTP-часть API сервиса
- [ ] Игра корректно работает на десктопе, есть все экраны
- [ ] Код на 95% на TypeScript
- [ ] Версия Node указана в `.nvmrc` или `engines`, не ниже 12

## 1.6 Безопасность

- [ ] Приложение защищено от XSS
- [ ] Приложение защищено от DOS
- [ ] Все эндпоинты, требующие авторизации, недоступны неавторизованным пользователям

## 1.7 Надёжность

- [ ] Приложение работает без подключения к интернету
- [ ] Обрабатываются ошибки сервера и клиента
- [ ] **Белых экранов быть не должно**

## 1.8 Web API

- [ ] Canvas API
- [ ] Fetch API
- [ ] Ещё четыре дополнительных Web API — например, LocalStorage, Notifications

## 1.9 Собственные реализации

- [ ] Один HOC написан самостоятельно
- [ ] Один хук написан самостоятельно
- [ ] Свой метод сортировки, добавленный в прототип массивов или объектов.
      Вызывать `sort` нельзя
- [ ] Своя очередь. Для задач, предполагающих очередь, использовать массив нельзя
- [ ] Свой стек. Для задач, предполагающих стек, использовать массив нельзя

## 1.10 Качество

- [ ] Lighthouse ≥ 50% по каждой метрике
- [ ] Тестами покрыты базовые компоненты

# 2. Технологии курса (справочно)

Курс перечисляет их как «технологии, которые будут использованы». Требования применить
каждую из них нет — есть требования из раздела 1. Колонка «статус» фиксирует наше решение,
чтобы на защите не пришлось вспоминать, почему чего-то нет.

| Технология | Версия | Статус | Комментарий |
|---|---|---|---|
| TypeScript, JavaScript | ≥ 3.8 | используем | TS; доля ≥ 95% — пункт 1.5 |
| React | ≥ 16.8 | используем | 18, из шаблона |
| Redux | — | используем | Redux Toolkit |
| React Router | — | используем | v6, из шаблона |
| Vite | ≥ 3 | используем | из шаблона |
| Node.js | ≥ 12 | используем | **единственное явное обязательство списка:** версия в `.nvmrc` или `engines` — задача 1.3 |
| PostgreSQL | ≥ 11 | используем | задача 2.2 |
| MongoDB | — | не используем | альтернатива PostgreSQL, взяли Postgres |
| Sequelize | — | используем | задачи 2.2, 2.6; в списке технологий отсутствует, требование идёт из пункта 1.4 |
| Jest | — | используем | из шаблона |
| Docker | — | используем | `docker compose` из шаблона, прод-стенд 1.9 |
| Nginx | — | используем | reverse-proxy и SSL, задача 1.14 |
| SSL | — | используем | задача 1.14 |
| Proxy | — | используем | dev-прокси 1.10, прод — nginx 1.14 |
| Yandex Cloud | — | используем | прод-стенд, решение от 2026-08-13 |
| CI/CD | — | используем | задачи 1.6, 1.8 |
| SSR | — | используем | уже в шаблоне |
| Canvas API | — | используем | эпик 9 |
| Web API | — | используем | Canvas и Fetch + четыре дополнительных — пункт 1.8 |
| Web Workers | — | используем | Service Worker: офлайн и уведомления (11.1, 11.2, 11.4). Курс сам определяет их назначение именно так |
| ESLint, `.editorconfig` | — | используем | из шаблона, донастройка в 1.4 |
| Stylelint | — | **решение не принято** | в шаблоне нет; для styled-components нужен `postcss-styled-syntax`, ~0.5 дня |
| Препроцессоры или PostCSS | — | частично | styled-components (внутри stylis) + PostCSS, встроенный в Vite. Отдельный препроцессор не берём — решение в `decisions.md` |
| OAuth | — | **решение не принято** | вход через Яндекс, ~1 день на API курса. Завязан на прод-домен (`redirect_uri`) |
