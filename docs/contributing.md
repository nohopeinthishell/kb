# Как мы работаем

Правила разработки, работы с git и ревью. Договорённости команды из четырёх человек —
их смысл в том, чтобы никто не ждал друг друга дольше суток и чтобы `dev` всегда собиралась.

Если правило мешает — обсуждаем и меняем.

---

## 1. Задача

Работа начинается с карточки на доске в GitHub Projects, а не с кода.

- Прежде чем писать код, переведите карточку в «В работе» и назначьте на себя.
- **Больше одной карточки «В работе» на человека — нельзя.** Начали новое — сначала
  доведите или верните на доску текущее.

**Definition of Done.** Задача закрыта, когда:

- код в `main`;
- CI зелёный;
- документация в `docs/` обновлена, если менялись архитектура, правила или команды;
- карточка на доске переведена в «Готово».

---

## 2. Ветки

Основная ветка `main` - Прямые пуши запрещены, сюда только мёрж через ПР

Правила именования:

- Имя ветки — номер задачи с доски и короткий слаг латиницей:
  `kb-146-jest-vite-config`, `kb-152-forum-page`. Номер обязателен: по нему GitHub
  связывает ветку и PR с карточкой.
- Одна задача = одна ветка = один PR.
- Номер из имени ветки автоматически попадает в сообщение коммита: хук
  `prepare-commit-msg` превращает `фикс конфига` в `kb-146: фикс конфига`.
  Если после `git pull` хук не срабатывает — выполните `yarn lefthook install`.

---

## 3. Pull request

- Целевой размер — **до 500 изменённых строк**. Рефакторинг и новую функциональность разносим по разным PR.
- Заполняем шаблон целиком. Для любых изменений в UI скриншот или видео —
  обязательны: это экономит ревьюеру запуск проекта.
- **Один обязательный апрув.** Ревьюер назначается по кругу, чтобы не сложилось,
  что все PR смотрит один человек.
- Мержит автор PR

---

## 4. Ревью

**Срок — 24 часа.** Не посмотрели за сутки — автор пингует в чате.

Замечания помечаем уровнем, иначе любая мелочь читается как блокер:

| Префикс | Значение |
|---|---|
| `[blocker]` | Без исправления не мержим |
| `[nit]` | Вкусовщина, автор вправе не согласиться |
| `[вопрос]` | Не понял, объясни |

Как ревьюим:

- Обсуждаем код, а не человека: «здесь будет утечка при размонтировании»,
  а не «ты забыл».
- О форматировании и стиле не спорим — это работа eslint и prettier. Если спор
  повторился дважды, правило уходит в конфиг линтера, а не в комментарии.
- После двух раундов комментариев — созвон на десять минут вместо третьего раунда
  переписки.
- Резолвит тред тот, кто его открыл.

На что смотрим в первую очередь — жёсткие правила из `AGENTS.md` и границы слоёв
из [architecture.md](architecture.md): SSR, тема в cookie, регистрация страниц парой.
