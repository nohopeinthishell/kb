# AGENTS.md

Инструкции для AI-помощников, работающих с этим репозиторием.
Для людей — начните с `README.md` и `docs/`.

## Что за проект

Браузерная игра «Таверна» — пошаговый экономический симулятор на React + TypeScript
с отрисовкой игрового зала через Canvas API. Учебный проект курса «Мидл фронтенд-разработчик».
Команда — 4 человека, срок — 14 недель.

- Что за игра и как в неё играют — `docs/game-plan.md`
- Слои и границы модулей — `docs/architecture.md`

## Команды

```
yarn bootstrap                        # обязательно перед первым запуском
yarn dev                              # клиент + сервер
yarn dev --scope=client               # только клиент
yarn dev --scope=server               # только сервер
yarn lint
yarn format                           # prettier
yarn test                             # jest + react-testing-library
yarn build
yarn preview --scope client           # посмотреть прод-сборку
yarn lerna add {dep} --scope client   # зависимость клиенту
yarn lerna add {dep} --dev --scope server   # dev-зависимость серверу
```

Продакшен-окружение локально: `node init.js`, затем `docker compose up`
(nginx + node + postgres). Отдельный сервис — `docker compose up server`.

Git-хуки на lefthook. Пропуск проверок через `--no-verify` — только в крайнем случае.

## Структура

Монорепа на Lerna из шаблона курса.

```
packages/client/   # React, Vite, SSR
packages/server/   # Express, PostgreSQL, Sequelize — форум и темизация
docs/              # документация проекта
```

Авторизация, профиль и лидерборд берутся из **готового API курса**, свой бэкенд их не дублирует.
Свой сервер отвечает только за форум и хранение тем.

## Жёсткие правила

Нарушение любого из них — повод отклонить изменение.

**SSR.** Шаблон рендерит на сервере. Никаких обращений к `window`, `document`,
`localStorage` на верхнем уровне модуля — только внутри `useEffect` или за проверкой
окружения. Компонент с canvas монтируется исключительно на клиенте.

**Тема — в cookie, не в localStorage.** Сервер должен знать тему в момент рендера,
иначе на каждой загрузке будет мигание. В БД тема тоже сохраняется — требование курса.

**Страницы регистрируются парой.** Каждая страница экспортирует компонент и функцию
`initXxxPage` для загрузки данных, обе прописываются в `routes.tsx`. Без этого SSR
для страницы не работает. Образец — `docs/architecture.md`, раздел 6.

**Границы слоёв игры.**
```
game/core/    правила. Чистый TS, не импортирует React, Redux, canvas, fetch.
game/render/  отрисовка на canvas. Знает типы из core, не знает правил.
game/ui/      React-компоненты. Правил игры не содержат.
```
Наружу из `core` торчат три функции: `tick` (переход недели), `applyAction` (действие
игрока внутри недели) и `forecast` (прогноз для кнопки «Следующая неделя»). Прогноз
считается там же, где и сам переход, — иначе формула разъедется на первой правке баланса.

Ремонт запускается одной кнопкой без выбора цели на canvas. UI передаёт в `applyAction`
действие `repairTable` без `tableId`; `core` сначала выбирает сломанный стол, затем
изношенный, и отклоняет действие, если ремонтировать нечего. Правило ремонта живёт
только в `game/core/`.

Если формула или правило оказались в `.tsx` — это ошибка.

**Модули импортируются только через `index.ts`.** `modules/forum/ui/TopicRow` —
запрещённый импорт, `modules/forum` — правильный.

**Цвета — только из объекта темы** (styled-components `ThemeProvider`).
Никаких хардкоженных hex, включая палитру canvas: рендер получает тему параметром.

**TypeScript строгий.** `any` не проходит ревью. Целевая доля TS в проекте — 95%.

**Состояние.** Глобальное — Redux Toolkit со типизированными слайсами. Локальное для
компонента — `useState`. Серверные данные не дублируются в сторе руками.

**Структуры данных.** В `lib/` лежат собственные реализации сортировки, очереди и стека.
Не заменять их на `Array.prototype.sort`, массивы или библиотеки — это требование курса.

## Соглашения

- Структура клиента: `pages/`, `components/`, `modules/`, `slices/`, `api/`, `hooks/`,
  `game/`, `lib/`. Что куда класть — таблица в `docs/architecture.md`, раздел 3.
- В `components/` попадает только то, что не знает о домене. `Button` — да,
  `TopicRow` — нет, он живёт в `modules/forum/ui/`.
- Стили через styled-components (так в шаблоне), не CSS-модули.
- Игровые события описываются данными в JSON, а не кодом. Добавить событие =
  дописать объект в файл, ничего не меняя в логике.
- Хуки в `useCamelCase`, компоненты в `PascalCase`, файлы совпадают с именем экспорта.

## Чего не делать

- Не предлагать библиотеки для canvas (Pixi, Phaser) — по требованию курса
  используется чистый Canvas API.
- Не расширять объём игры. Список вырезанного — в `docs/game-plan.md`, раздел
  «Чего в игре нет». Он вырезан осознанно.
- Не переносить логику игры в компоненты. Если правило игры оказалось в `.tsx` — это баг.
- `packages/client/server/` — SSR-сервер шаблона, а не наш бэкенд (наш — `packages/server/`).
  Менять его можно, но только отдельным PR и с объяснением зачем: серверный 5xx, статусы
  ответов, `nonce` под CSP — это задача 1.15. Мимоходом, заодно с фичей, — нет.
